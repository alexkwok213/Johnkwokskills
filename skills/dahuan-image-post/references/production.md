# 贴图制作与检查

## 共用资料，分别写表达

从文章定稿、事实记录和已核实配图起步。每页先确定读者得到什么，再选截图与短句。两版可以详略不同，关键条件、数据和归属保持一致。功能指令是供读者尝试的问法，不凭改写指令声称已经得到相应结果。

WorkBuddy 这次的顺序是：首图、五种用法、知识库、技能与专家、接入步骤、使用清单，共十张。它适合多用途科普。事件可以用少量页讲变化与证据，教程可以用更多页展示关键操作；不沿用不相关的栏目。

## 可编辑排版

默认每页 1080×1440，3:4。可以共用字号、页边距、配色与页码，但按画面调整布局。首图、用途、步骤和总结不必使用同一模板。重要文字靠内放，避免首图中的「用法」等完整词被拆到孤零零的一行。

HTML/CSS 适合排版准确中文、真实截图和说明。将截图作为资源嵌入，可用容器展示局部；保留原图，记录来源与显示范围。先看原图再选局部，不让按钮、关键数据或结论被无意裁断。需要对照全貌时，在同页或相关页保留定位信息。

在 1080 宽画布中，曾使用约 64–72 像素页边距、60–70 像素标题和30像素左右说明。这些是起点，按字数和手机效果调整。主要信息要在约 360–390 像素显示宽度下仍能直接阅读；截图细节需要放大时，点击原图应能看清。灰色图注居中，检查底部说明与署名是否拥挤。

对中文密集页面优先用稳定字体与排版；新插画按 imagegen 制作。截图中的产品内容不交给生成模型重绘。若复用已有插画，明确其用途是表达主题。

## 浏览器导出时避免截短

使用当前可用的浏览器工具并遵守其技能。确认图片与字体加载完成后再导出。可以通过独立页面或页码参数一次只显示一张 1080×1440 卡片。

本次 Tabbit 的已验证写法是：

```js
await page.screenshot({
  fullPage: true,
  clip: { x: 0, y: 0, width: 1080, height: 1440 },
  scale: 'css'
});
```

仅设 `clip` 而未设 `fullPage: true` 时，曾实际得到 1080×907，底部被视口截掉；高分屏还需确认导出是否按 CSS 像素。不同工具可能处理不同，不能把请求参数当作输出尺寸。读取实际文件尺寸后再判定通过；保存截图回执或渲染器输出到文章目录，不能只留下工具临时位置。

## 每页及整套交付

1. 看每张实际导出图：标题与内容是否一致，截图是否清楚，文字有无错字、遮挡、溢出及断行；灰色说明是否居中。
2. 看手机大小：不放大能否抓住这页的结论、任务或操作；信息过密就重组或分图。
3. 看整套：顺序与页码一致，删掉重复页；逐项核对影响结论的两版事实。改图后重建预览与压缩包，避免交付旧图。
4. 核对实际数量、尺寸和打包内容，交付可上传图片、整套预览、压缩包、标题与短正文。可编辑源、原图及出处放工作文件中，不混入上传顺序。

在预览中说明上传顺序与实际尺寸。未进行平台上传时，只报告本地验收结果。
