# 公众号文章

写给阅读：读者可以回看、可以扫读，所以要让段落推进理解，让重点能被扫到。

## 先定这篇帮谁解决什么

先用一句话说清：这篇帮谁、回答什么问题。再选主目的，一篇只有一个优先。

| 主目的 | 读者读完得到什么 | 常见推进 |
|---|---|---|
| 功能科普 | 是什么、能替自己做什么、从哪开始 | 新变化或代表结果 → 按任务讲用途 → 接入条件 |
| 实操教程 | 能照着完成一件事 | 任务和成果 → 准备 → 关键操作 → 检查结果 |
| 案例拆解 | 谁遇到什么问题、怎么做成、哪些能借鉴 | 需求 → 行动 → 成果与成本 → 判断 → 读者能试的一步 |
| 变化观察 | 一组事件说明了什么、跟我有什么关系 | 有辨识度的变化 → 案例推进 → 判断与选择 |

新命题时比较两三个实质不同的角度：帮谁、主线、哪个案例最能展开主线。按读者收获和材料支撑推荐一条。标题和开头按同一个承诺打磨，标题给点开的理由，开头尽快用具体的痛点、动作或成果接住。

## 写

- 开头碰到事情。从事件、人、动作或成果开始，不交代「我读到了某篇报道」。
- 一段做一件事：讲动作、补背景、算一笔账、解释原因或下判断。下一段回答上一段留下的问题，不重复同一个态度。
- 案例按作用排：一个主案例讲清行动过程，辅助案例各补一个新用途、成本或限制。作用相同的合并。
- 解释在读者想知道的时候出现，从他熟悉的动作讲起，讲到够继续读就停。专业词先想能不能换成普通说法。
- 第一人称只用于有记录的实操、用户确认的经历和有依据的判断。没做过的事不写成做过。
- 正文直接讲事情本身。缺少的细节直接略过，不写收集或核查过程。
- 结尾回扣开头的需求或问题，落到读者自己的选择上。可以有情绪和升华，但要与前面的内容相连，不靠时代口号。

## 让扫读的人也带走东西

关键事件、用时、成果和判断选择性加粗；最关键的阶段性总结和结尾共鸣句可以独立成段、加粗标红。只看标题和加粗部分，读者应该能抓住主要价值。不要整段加粗，也不要只加粗产品名。

图跟在对应的成果或动作后面，图注说清画面里的用途或变化。

## 写完

冷读：标题的承诺正文兑现了吗？每段给读者增加了什么？普通读者能说清这个东西有什么用吗？然后查 [voice.md](voice.md)。
