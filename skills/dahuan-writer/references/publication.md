# 公众号排版、复制与封面

写稿与技术核验记录分开保存。用户需要可发布稿时，主动检查配图、重点排版、复制入口和封面；用户只需要草稿或已有成品时，按当前范围处理。

## 正文重点与配图

- 正文中 AI 统一大写，网址和代码原样保留。
- 关键事件、用时、成果和判断选择性加粗；最关键的阶段性总结及结尾共鸣句可独立成段、加粗标红。本次色值为 `#c62828`，后续按稿件设计调整。
- 图跟在对应成果或动作后面。软件案例优先选真实界面，游戏案例选对应游戏或项目画面；旧图、原作画面和实际复刻成果分别标清，不冒充实测。
- 热度一句话说明，增长图旁交代它是当前图还是早期快照。不要沿用过时的 Star 数。
- 图注帮助看懂操作或用途，不交代「我从某报道找到了图」。发布稿默认不附「资料与图片出处」，来源与必要核验记录保存于后台；必要署名和原水印保留。

## 检查真正复制出的富文本

本次实际出现的微信「内容结构检测」报告：`text-align:start` 非标准对齐值，以及图片段落固定宽度造成布局差异。只看本地网页正常，不能保证粘贴后的 HTML 正常。

使用 `text-align:left` 等标准对齐值；图片 `width:100%;max-width:100%;height:auto`，避免固定像素宽度，保留图片比例与原始尺寸信息。正文格式以内联样式传递，复制内容排除按钮、页头日期和单独填写的标题。

已有普通段落、图片、引用和重点句组成的 HTML 预览时，可复用 [公众号正文复制代码](../assets/wechat-copy.js)。它是本次已实测的复制逻辑，不是任意网页的通用清洗器。接入约定：

```html
<aside>
  <button id="copy-wechat" type="button">复制公众号正文</button>
  <span id="copy-message" role="status" aria-live="polite">标题请单独填入公众号标题栏。</span>
</aside>
<article>
  <!-- h1 标题和 .status 页头不会进入复制正文；.caption 表示图片说明。 -->
</article>
<script src="wechat-copy.js"></script>
```

将代码复制到交付目录并接在正文后。它优先写入 `text/html` 与 `text/plain` 两种格式；只有 API 不支持时才回退到复制事件。复制权限失败时明确提示，不把失败写成成功。

确认图片已加载后，在浏览器点击按钮并读取实际复制内容：文字一致、图片数正确、加粗与标红保留、没有 start/end 对齐值或固定宽度，也没有混入标题及控件。复杂表格等新增组件需要按实际复制结果检查。

用户遇到结构警告时，按弹窗链接读取当前[微信排版规范](https://developers.weixin.qq.com/doc/service/guide/product/plugin_spec.html)，修复后重新复制粘贴。分别记录「源页与剪贴板检查通过」和「公众号实际粘贴验收」，不把前者冒充后者。实际公众号还需确认图片正常加载、格式保留和手机显示。

## 同一封面兼顾两种裁切

需要实际设计或生成封面时，使用同系列的 `dahuan-cover` 技能。独立技能包含文案提炼、AI 生成、两种裁切检查及本次提示词案例；未安装时可按本节原则完成，或从[技能仓库](https://github.com/alexkwok213/Johnkwokskills/tree/main/skills/dahuan-cover)获取。

公众号封面按本次用户要求采用 2.35:1 横版，并从同一张图截取 1:1 方形。之后完整发布任务主动提醒这项需求；用户已有封面或指定其他规格时按当前要求处理。

设计时先确保中央方形独立成立，再用两侧补充内容。对于宽 `W`、高 `H`、`W/H=2.35` 的画布，中央方形范围为 `x=(W-H)/2` 至 `(W+H)/2`，即横向约 28.7% 至 71.3%。标题、人物及核心成果的完整轮廓留在这一范围内，四周留出裁切余量；两侧只能放可舍弃的补充画面。

文字短、清晰、字号足够缩略图阅读。默认沿用大欢已接受的简洁布局，主体与重点句优先，不堆产品 logo、长标题、小字和装饰。用户要求 AI 生成时用 imagegen；生成界面只是封面视觉表达，不用于证明真实产品功能。

生成后检查中文是否正确、两种裁切是否保留完整信息、主体边缘是否紧贴裁框。读取实际像素尺寸，生成图接近指定比例时说明上传裁框的调整，不把近似比例宣称为精确尺寸。保存成品、最终提示词和必要的裁切说明，封面作为独立上传文件，不混进正文复制内容。
